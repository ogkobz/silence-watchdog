# silence-watchdog

Сторож, который следит не за ошибками, а за молчанием.

## Зачем

Интеграции чаще всего отказывают тихо. Слетевшая переадресация, отозванный токен,
выключенный кем-то вебхук — ни один из этих случаев не даёт исключения в логе.
Система просто перестаёт получать данные, и это замечают через неделю по пустой
воронке.

Мониторинг ошибок такое не ловит по определению: ошибок нет. Нужен обратный
подход — считать нормой поток событий и поднимать тревогу, когда поток пропал.

## Как работает

Источник сообщает о жизни сам:

```
POST /heartbeat/novofon-webhook   -> 204
```

Раз в минуту сторож сверяет время последнего события с допустимым окном тишины
из конфигурации и шлёт алерт в Telegram, когда окно превышено.

```yaml
sources:
  - name: novofon-webhook
    max_silence: 72h
  - name: avito-leads
    max_silence: 6h
    quiet_hours: "23:00-08:00"   # ночью тишина — норма

notify:
  telegram_chat_id: "${TELEGRAM_CHAT_ID}"
  repeat_after: 12h
```

`GET /status` показывает по каждому источнику, когда он был слышен в последний раз
и сколько молчит сейчас.

## Три решения, которые здесь главные

**Источник, не приславший ни одного события, считается молчащим с момента старта,
а не «данных пока нет».** Иначе интеграция, сломанная с первого дня, не даст алерта
никогда — а это самый частый случай в реальности.

**Окно тишины подавляет алерт, но не обнуляет таймер.** Ночью звонков нет, и это
нормально; но если их нет и утром, счётчик уже идёт с вечера, а не с восьми утра.

**Повторный алерт по тому же источнику — не чаще `repeat_after`.** Сторож, который
пишет каждую минуту, выключается человеком на второй день, и дальше не работает
вообще.

Плюс мелочи, каждая из которых выучена на граблях: цикл проверки не умирает от
исключения внутри итерации; недоступный Telegram не роняет наблюдение; отсутствие
токена переводит сервис в режим журнала, а не мешает старту.

## Запуск

```
pip install -r requirements.txt
cp config.example.yaml config.yaml
export TELEGRAM_BOT_TOKEN=...  TELEGRAM_CHAT_ID=...
uvicorn watchdog.app:app --port 8080
```

Docker:

```
docker build -t silence-watchdog .
docker run -p 8080:8080 -v $PWD/data:/app/data \
  -e TELEGRAM_BOT_TOKEN -e TELEGRAM_CHAT_ID silence-watchdog
```

## Тесты

```
python -m pytest tests -q
```

24 теста: разбор конфигурации, окна тишины через полночь, троттлинг повторов,
источник без единого события, восстановление после молчания, хранилище.
